# Artifact Authoring

Keep artifacts concise and executable.

PRD defines user value, scope, non-goals, acceptance criteria, profile, risk, and constraints. Story records a narrow deliverable and acceptance criteria before implementation planning. DDD is required only for complex domain behavior, permissions, state machines, multiplayer, economies, persistence, payments, security, or cross-system behavior. FID is an implementation contract: modules, interfaces, data/state changes, edge cases, migrations, rollout risks, and test strategy. Acceptance records evidence against criteria; it does not redefine requirements.
